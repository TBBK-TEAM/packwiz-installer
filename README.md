# packwiz-installer
An installer for launching packwiz modpacks with MultiMC.

## Running the installer

It can be run on its own - the bootstrapper is optional:

```
java -jar packwiz-installer.jar --side server --full-sync https://example.com/pack.toml
```

`--help` lists all options and `--version` prints the version of the installer.

Alternatively, [the bootstrapper](https://github.com/comp500/packwiz-installer-bootstrap/releases)
can be used to keep the installer itself up to date:

```
java -jar packwiz-installer-bootstrap.jar -g -s server --full-sync https://example.com/pack.toml
```

Note that the bootstrapper updates the installer from the *upstream* releases by default: when using a
fork, point it at that fork's releases with
`--bootstrap-update-url https://api.github.com/repos/<owner>/<repo>/releases/latest`, use
`--bootstrap-no-update`, or just run the installer directly.

## Keeping the pack folder in sync

Files that were installed by a previous update, but which are no longer part of the pack (for example
mods, configs or resource packs that were removed from the pack), are deleted from the pack folder
automatically. If a deletion fails (for example because the file is locked by a running game/server),
the file is kept in the manifest and deleted on the next update instead.

Files that the pack never installed - mods, configs or resource packs that a player added - are **kept
by default**. Deleting them is opt-in, and each switch can be used on its own:

* `--prune-mods` removes leftover files in the folders where the pack installs mods (JARs only, unless
  `--prune-all` is used as well). Useful on a server to get rid of mods that were removed from the
  pack while the manifest was lost.
* `--prune-user-folders` removes leftover files of any type in the other folders the pack installs
  files into (`config/`, `resourcepacks/`, `defaultconfigs/`, ...). This deletes files that were added
  by hand, so it is meant for servers.
* `--prune-all` does all of the above with every file type, and also enables `--full-sync`.
* `--full-sync` additionally cleans up folders that the pack used to install files into (remembered in
  the manifest) and folders that are left empty. Combine it with `--prune-mods` or
  `--prune-user-folders` (or just use `--prune-all`).
* `--no-prune` disables every deletion.

Suggested use: servers that must not drift out of sync use `--prune-all`; clients should use the
defaults, so that a player's own mods, configs and resource packs are kept.

Cleanup also runs when the pack itself is already up to date, so files are removed even if nothing in
the pack changed. Only files inside folders that the pack installs files into are ever deleted - the
rest of the pack folder (the world, logs, `server.properties`, plugins, ...) is never touched. Hidden
files (`.foo`), `.disabled` files, `*.pw.toml` files and the manifest itself are never deleted, files
that are installed directly into the pack folder are only removed when the manifest says that the
installer put them there, and folders holding data generated by the game or server (`world/`, `logs/`,
`backups/`, `saves/`, ...) are never swept, even when the pack installs files into them.
